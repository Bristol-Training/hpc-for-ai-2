# HPC for AI - Part 2

## About this course

This course shows how to use Isambard-AI, a UK national supercomputer, to fine-tune a large language model (LLM) and use it in research. You will fine-tune Mistral 7B so that it learns to follow instructions, compare two ways of fitting fine-tuning onto one GPU (LoRA and QLoRA), and then call the model from a program to label about 30,000 UK news headlines.

## Prerequisites

You should be comfortable with Python, Jupyter and pandas, and know what a neural network and its training loop are, at the level of Introduction to AI. Some command-line experience is helpful. Part 1 of this course is useful but not required. You will need an Isambard-AI account, set up before the course; joining instructions will be sent in advance.

## What you will learn

- The difference between training, fine-tuning and retrieval-augmented generation (RAG).
- How LoRA and QLoRA make fine-tuning a 7-billion-parameter model fit on one GPU, and what each costs.
- How to fine-tune an LLM on Isambard-AI and check whether it worked.
- How to run a model quickly over many inputs with vLLM, and check its answers from a program.
- Good practice for working on a shared supercomputer.
- Optionally, how to profile GPU work with NVIDIA Nsight Systems.

## How the course runs

A 2-hour, hands-on session. Each attendee starts a JupyterHub session on Isambard-AI with 1 GH200 and runs a complete notebook, `notebooks/hpc-for-ai-2.ipynb`. Half the room trains with LoRA and half with QLoRA, so everyone can compare the two without training twice. The slides introduce each section; the notes explain every step and have an exercise for each section. Profiling is an optional section at the end.

This course is written with [Quarto](https://quarto.org), and follows the structure of [HPC for AI - Part 1](https://github.com/Bristol-Training/hpc-for-ai-1).

## Rendering

Install Quarto from <https://quarto.org/docs/get-started/>. No Python packages are needed to render: the notes show the course code but don't run it.

### Everything at once (recommended)

From the top-level folder, run:

```bash
python render.py
```

This creates the course pages in `resources/` and the website in `docs/`. It also checks that:

- the attendee versions contain no instructor notes, and
- every notebook code block in the notes matches a cell in `notebooks/hpc-for-ai-2.ipynb`.

### One output at a time

From a terminal in the `source/` folder (these write the HTML next to the `.qmd`, which git ignores; use `render.py` to update `resources/` and `docs/`):

```bash
# Instructor notes
quarto render hpc-ai-2-notes.qmd

# Attendee notes
quarto render hpc-ai-2-notes.qmd -M attendee:true --output hpc-ai-2-notes-attendee.html

# Slides
quarto render hpc-ai-2-slides.qmd
```

### Live preview while editing

From the `source/` folder:

```bash
quarto preview hpc-ai-2-notes.qmd     # instructor view
quarto preview hpc-ai-2-slides.qmd
```

## Publishing the website (GitHub Pages)

`render.py` builds the website into `docs/`:

| File | What it is |
|---|---|
| `docs/index.html` | The landing page: a short intro, the embedded slides, links to materials, then the attendee notes |
| `docs/slides.html` | Copy of `resources/hpc-ai-2-slides.html` (embedded on the landing page and opened full screen from it) |
| `docs/instructor.html` | Copy of `resources/hpc-ai-2-notes.html` |

The landing-page block lives at the top of `source/hpc-ai-2-notes.qmd`, inside `::: {.content-visible when-meta="site"}`, so it only appears in the website build.

To publish:

1. Run `python render.py`.
2. Commit and push, including the `docs/` folder.
3. One-time setup on GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**, then pick `main` and `/docs`.

The site appears at `https://bristol-training.github.io/hpc-for-ai-2/` a minute or two after each push. GitHub Pages sites are public, so anyone with the link can read the instructor version too.

## Editing the notes

The notes follow the house style of the existing JGI courses:

```markdown
::: {#exerciseN .callout-note icon=false title='Exercise'}
The exercise (one at the end of each section).
:::

::: {#answerN .callout-caution icon=false title='Answer' collapse="true"}
The answer (collapsed by default).
:::

::: {#keypointsN .callout-tip icon=false title='Key points'}
Important concepts.
:::
```

### Adding instructor-only content

Wrap anything that attendees should **not** see in a `content-hidden` block. It shows in the instructor version and is removed from the attendee version:

```markdown
::: {.content-hidden when-meta="attendee"}
::: {.callout-important icon=false title='Instructor notes'}
**Live demo:** ...

**Pitfalls:** ...
:::
:::
```

Keep the title `Instructor notes`: `render.py` searches for it to check that nothing has leaked into the attendee copy.

### Keeping the notes and notebook in step

Code blocks in the notes headed `filename="hpc-for-ai-2.ipynb"` are exact copies of cells in `notebooks/hpc-for-ai-2.ipynb`. If you change one, change the other: `render.py` stops with an error if they don't match. Code in exercise answers and in the slides is not checked, so you can shorten it there.

### Automatic checks when you commit

The repository uses [pre-commit](https://pre-commit.com) to run two checks every time you commit:

- [nbstripout](https://github.com/kynan/nbstripout) removes the outputs from the notebook, so results aren't committed or copied to Isambard-AI.
- [Ruff](https://docs.astral.sh/ruff/) checks the Python code in `render.py`, `setup/` and the notebook for errors. Its settings are in `ruff.toml`.

Set it up once, from the top-level folder:

```bash
pip install pre-commit
pre-commit install
```

Ruff can also reformat code (`ruff format`), but don't run it on the notebook: it would change the code cells so that they no longer match the notes.

## Setting up Isambard-AI for a course

See the **Instructor setup** section at the end of the instructor notes. In short:

1. The course runs in the training project, using the `interactive` reservation. Check with BriCS whether the project has a GPU limit.
2. Build the course kernel and download the model and data with `setup/build-environment.sh`, in a 1-GPU job (its final check needs a GPU). It also writes `kernels/install-kernels.sh`, which attendees run once to add the **Fine-tuning + Nsight** kernel to JupyterLab.
3. Copy the notebook, the headlines dataset and a trained fallback adapter for each mode into the course folder, then do a full dry run in JupyterHub.
